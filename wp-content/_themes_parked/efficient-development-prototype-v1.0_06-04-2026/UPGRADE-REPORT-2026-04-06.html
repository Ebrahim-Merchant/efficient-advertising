3. Security & Foundation Fixes

SECURITY PHASE 1 — DO FIRST These issues must be fixed before any visual upgrades. A beautiful site that gets hacked is worthless.

🚨 CRITICAL: WordPress Updates Are Disabled

File: functions.php — remove_core_updates()

This disables ALL security patches for WordPress core, plugins, and themes. Every known WordPress vulnerability since 2022 is exploitable on this site.

Fix: Remove the remove_core_updates() function and all hooks calling it. Enable auto-updates for minor releases.

🚨 CRITICAL: Weak OTP Generation

File: functions.php — OTP system uses rand()

PHP's rand() is not cryptographically secure. OTP codes could be predicted.

Fix: Replace with wp_rand() or random_int(100000, 999999). Add rate limiting (max 3 attempts per 10 minutes per email).

🚨 Hardcoded Analytics IDs

Google Analytics (G-38EQB75ZRX) and Google Ads (AW-854448823) are hardcoded in header.php.

Fix: Move to theme options or use a dedicated analytics plugin (e.g., Site Kit by Google) for proper consent management and GDPR compliance.

⚠️ HTTPS & Security Headers

Ensure production deployment has: SSL/TLS certificate, HSTS header, Content-Security-Policy, X-Frame-Options, X-Content-Type-Options.

4. Speed & Core Web Vitals

PERFORMANCE Target: <2 second load, LCP <2.5s, CLS <0.1, INP <200ms. Currently failing all benchmarks due to render-blocking scripts and duplicate resource loading.

Critical Performance Issues

🚨 Scripts Loaded TWICE — header.php + footer.php

jQuery, Bootstrap JS, Owl Carousel, WOW.js, and LightSlider are loaded in BOTH header.php and footer.php. Every page downloads and parses each script twice.

Impact: ~500KB+ wasted bandwidth per page load. Double JavaScript execution.

Fix: Migrate ALL scripts to wp_enqueue_script() in functions.php. WordPress automatically deduplicates. Load scripts in footer with in_footer: true.

🚨 8 Render-Blocking Resources in <head>

8 CSS files and 5 JS files loaded synchronously in <head> without defer or async. Browser cannot render anything until all are downloaded and parsed.

Fix:

  • Critical CSS: Inline above-the-fold CSS (~15KB) directly in <head>
  • Non-critical CSS: Load with media="print" onload="this.media='all'" pattern
  • All JS: Add defer attribute (or move to footer)
  • Third-party CDN scripts (LightSlider): Self-host or remove if unused
⚠️ 1,000+ Lines of Inline CSS

header.php (~450 lines), footer.php (~150 lines), and each template (200-500 lines) inject massive <style> blocks into the HTML.

Impact: Increases HTML size by ~40-80KB per page. Cannot be cached by browser.

Fix: Extract all inline CSS into organized external stylesheets:

  • css/header.css — header/nav styles
  • css/footer.css — footer styles
  • css/hero.css — homepage hero slider
  • css/product.css — single product page
  • css/taxonomy.css — category archive page
  • css/service-page.css — shared service landing page styles

Image Optimization

⚠️ No Modern Image Formats or Responsive Images
  • No WebP or AVIF conversion — all images are PNG/JPG
  • No srcset / sizes attributes — same large image served to all screen sizes
  • No loading="lazy" on below-fold images
  • Hero image preloaded ✓ (good)

Fix:

  • Register custom image sizes: efficient-hero (1920×800), efficient-product (800×800), efficient-thumb (400×400)
  • Use wp_get_attachment_image() which auto-generates srcset
  • Install ShortPixel or Imagify for WebP auto-conversion
  • Add loading="lazy" to all non-LCP images
  • Add fetchpriority="high" to LCP image

Recommended Animation Library: GSAP (GreenSock)

Why GSAP Over Animate.css
  • Performance — GSAP uses requestAnimationFrame and optimizes for 60fps. Animate.css uses CSS keyframes which can't be controlled mid-animation.
  • ScrollTrigger — Pin sections, scrub animations, create scroll-linked timelines. Much more powerful than WOW.js.
  • Staggering — Animate product cards one-by-one with cascading delays. Creates premium feel.
  • SplitText — Animate individual characters/words in headlines. "Efficient Advertising" reveals letter by letter.
  • License — Free for standard use. "No Charge" license covers most features.

13. Tech Stack Modernization

CODE The foundation must be solid before adding features. This means proper WordPress patterns, modern CSS, and clean JavaScript.

Migration Plan: Bootstrap 3 → Modern CSS

Why Remove Bootstrap 3
  • Bootstrap 3 is ~150KB (CSS + JS) — you're using maybe 5% of it (grid + navbar)
  • It loads jQuery as a dependency — jQuery is already loaded by WordPress
  • CSS Grid and Flexbox (native CSS) can replace Bootstrap's grid with zero dependencies
  • Bootstrap 3's navbar collapse requires JS — a CSS-only hamburger menu is simpler and faster

Approach: Don't remove Bootstrap overnight. Gradually replace Bootstrap classes with custom CSS utilities, then remove the library when all dependencies are eliminated.
